# EasySlides Presentation Production Contracts

EasySlides keeps the existing `deck_plan.json` and `component_plan.json`
backward-compatible. Production delivery adds four explicit artifacts:

- `content_plan.json`: deck message, per-slide question/takeaway/evidence,
  claim ledger, and source coverage decisions.
- `design_plan.json`: design language, density, form candidates, runner-up,
  rhythm, and signature move.
- `critic_report.json` and `arbiter_report.json`: independent review records.
- `deck-gates.json`: fail-closed handoff report with SHA-256 hashes for the
  input artifacts.

## Typical Flow

```powershell
python scripts/easyslides.py clarify init --route new_deck --out clarification_request.json
python scripts/easyslides.py plan deck_plan.json --component-plan component_plan.json --out-dir .
python scripts/easyslides.py content-contract content_plan.json --deck-plan deck_plan.json --json
python scripts/easyslides.py design-contract design_plan.json --content-plan content_plan.json --json
python scripts/easyslides.py deck-gates . --repo-root <repo-root> --report deck-gates.json --json
```

The plan builder intentionally emits `plan_status: draft`. A user or an
upstream planner must make the evidence and design decisions explicit and set
both plans to `approved` before the delivery gate can pass.

## Template Packages

Reusable semantic templates are registered as packages with a version,
canonical source ownership, capability level, entrypoints, canvas
compatibility, and dependency lock:

```powershell
python scripts/easyslides.py template-package init templates/layouts/nsfc_defense --version 0.2.0 --status review --json
python scripts/easyslides.py template-package validate templates/layouts/nsfc_defense --json
python scripts/easyslides.py template-package rebuild --json
python scripts/easyslides.py template-package list --json
python scripts/easyslides.py template-compile templates/layouts/nsfc_defense --write --json
```

The package manifest lives beside the template as `template_package.json`; the
repository registry is `templates/template_registry.json`. The registry is
generated by discovery and contains both managed packages and legacy template
compatibility entries.

## Slide Compilation

Production rendering resolves the complete composition before touching SVG or
PPTX:

```powershell
python scripts/easyslides.py slide-compile deck_plan.json `
  --template nsfc_defense `
  --out slide_ir.json `
  --svg-out rendered_svg `
  --pptx-out output.pptx `
  --json
```

`slide_ir.json` records the selected shell, body variant, component instances,
regions, z-order, slot bindings, and resolved payload. SVG and native PPTX are
two render targets of the same IR.
