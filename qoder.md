# EasySlides for Qoder

Use the three plugin-local skills in `skills/` and the shared operating guide
`SKILL.md`. Read `references/qoder.md` before the first presentation task. Paths
in this file are relative to the installed plugin root, not the user's cwd.

Ask for unresolved choices in Qoder's conversation or its user-question tool.
First confirm native editable production versus image generation followed by
editable reconstruction. For native production without an explicit template,
use `academic_general`; confirm theme color and existing discipline theme images
versus a newly generated topic image. Inspect supplied materials for discipline,
presenter, institution and date, and ask only about missing facts. User choices
and explicit omissions take precedence.

Use Qoder's actual file, shell and research tools. Image generation requires an
available host tool or a configured backend; a Codex-only tool name in shared
guidance does not imply it exists in Qoder. Explain a missing capability and
resolve the route with the user before proceeding.

Treat the installed plugin as read-only. Write projects, outputs and Python
environments in the user's workspace. Check Python 3.10+ and run the packaged
doctor before producing slides; install missing dependencies in a local virtual
environment through Qoder's normal permission controls. Preserve the shared
evidence, text hierarchy, layout, pagination and rendered-review requirements.
